# yt-dlp Archival Pipeline — Project Summary (for a fresh conversation)

## What this is
A personal YouTube archival pipeline built around yt-dlp, ffmpeg, and PowerShell 7 (`pwsh`). One command (`ytdl <url>`) downloads a video with subtitles/thumbnail/description/chapters/metadata, embeds everything possible into a final `.mkv`, fetches all comments, organizes everything into a structured per-video folder tree, computes checksums, maintains a manifest, and keeps a plain-video-only copy in a separate "Pure Video" library.

**Two parallel, maintained versions exist:** one for Windows (PowerShell 5.1 originally, migrated to `pwsh` 7.6.4), and a Linux/Ubuntu 26.04 port, produced late in the process. They are functionally equivalent; only paths and a couple of OS-specific mechanisms differ (see below).

## The four files (same architecture on both OSes)
1. **`ytdl.bat`** (Windows) / **`ytdl`** (Linux, bash) — thin entry point. Takes a URL, calls `run_ytdlp.ps1`.
2. **`run_ytdlp.ps1`** — sets up paths, does a throttled (once/24h) dependency-update check, snapshots `archive.txt`/manifest before each run, logs session start/end, invokes yt-dlp with the config file.
3. **`yt-dlp.conf`** — the actual yt-dlp options: format selection, subtitles, thumbnail, metadata embedding, output-path templates, retry/backoff tuning, and the `--exec` hook that fires `postprocess.ps1` after each video.
4. **`postprocess.ps1`** — runs once per video after download. Does: locate/parse `info.json` (with a fallback if missing), preserve the original-format thumbnail alongside the converted PNG, run a **separate comments-only pass**, merge comments into the sidecar `info.json`, **re-embed** the now-comment-complete `info.json` into the `.mkv` via a direct `ffmpeg` remux, compute SHA-256 checksums for every file, write a per-video manifest, copy the plain video to "Pure Video" (full descriptive filename), maintain channel-level and global manifests, refresh channel info (avatar/banner/description, throttled 6h), and sweep empty leftover folders from the temp/incomplete directory.

## Folder/file naming scheme (current, as of the last edit)
- Per-video folder: `<uploader> - <upload_date> - <id> - <title>` (uploader capped to 40 chars, title to 60 chars via yt-dlp's `%(field).Ns` template syntax) — this is the ONLY place the full descriptive name appears.
- Files inside that folder use short, fixed, role-based names instead of repeating the full name: `Final Video.mkv`, `Subtitles.<lang>.vtt` (language auto-inserted by yt-dlp regardless of base name), `Thumbnail.png` (+ original-format copy, e.g. `Thumbnail.webp`, preserved separately), `Description.description`, `Info.info.json`, `Link.<ext>`.
- Subfolders per video: `Final files/`, `Subtitles/`, `Images/`, `Video metadata/`.
- The **Pure Video** copy is the one exception: it deliberately uses the full `<uploader> - <date> - <id> - <title>.<ext>` name (built from the parent folder name + actual extension, not reconstructed from raw JSON, to avoid re-doing yt-dlp's own filename sanitization).
- No `--trim-filenames` (was removed — became dead weight once filenames got shortened; folder-name length is still bounded by the `.40s`/`.60s` field truncation).

## Non-obvious things discovered the hard way (read this before touching the config)
- **`--paths` (`-P`) does NOT expand `%()s` template fields — only `-o`/`--output` does.** This was the root cause of an early, major bug (folders literally named `%(uploader)s`, nothing sorted per-video). All per-video folder structure now lives in `-o` templates; `--paths` is only ever a static literal root.
- **`--exec` with plain `%()s`/`%()l` field conversions is blocked by yt-dlp** (security fix, CVE-related) — must use `%()q` (self-quoting) instead, and not wrap it in extra literal quotes.
- **Comments vs. expiring URLs**: video/audio/subtitle URLs are signed with a short expiry at extraction time. A single video's comments can take 30–60+ minutes to fetch (thousands of comments, paginated). If comments were fetched as part of the main download, the subtitle (and theoretically video/audio) URLs could expire before use, causing 404s — and by default a subtitle failure aborted the ENTIRE video, discarding all the already-fetched comments. Fixed by: (a) removing `--write-comments` from the main pass entirely, (b) `postprocess.ps1` running a **separate** yt-dlp invocation (`--skip-download --write-comments`) after the main video is safely done, merging the result into the sidecar `info.json`, and (c) adding `--ignore-errors` as a safety net for any remaining sub-step failures.
- **`--embed-info-json` embeds whatever info.json exists at that point in the pipeline** — since comments are fetched afterward now, embedding was moved out of yt-dlp's own config entirely. `postprocess.ps1` does its own `ffmpeg -attach ... -map 0 -c copy` remux *after* the comments merge, writing to a temp file first and only swapping it in on success. Important subtlety handled: the `-metadata:s:t:N` mimetype tag must target the correct new attachment stream index (found via `ffprobe`), otherwise it mislabels the already-embedded thumbnail too.
- **`--extractor-retries infinite` is dangerous** — with no backoff, it can hammer the same failing request hundreds of times without ever giving up (this actually happened and required killing the terminal). Use a bounded value (currently 100) plus `--retry-sleep "extractor:exp=1:30:2"` for real exponential backoff. This is scoped to `extractor:` only and doesn't interact with `--sleep-requests`/`--sleep-subtitles`/`--sleep-interval` (those are proactive pacing, not retry backoff — separate mechanisms).
- **`--write-storyboard` does not exist** in yt-dlp (an earlier, since-superseded version of this config wrongly assumed it did).
- **`--ignore-config`** is used on every yt-dlp invocation (main and the comments/channel-info sub-calls) to stop yt-dlp from silently auto-loading a stray `yt-dlp.conf` from the current directory / `%APPDATA%` / next to the binary — this was a real, previously-hit bug (a leftover config file injected an old, invalid `--exec` line).
- **`cmd.exe` batch files split arguments on `=` as well as spaces** — an unquoted YouTube URL (`...watch?v=abc123`) was silently truncated at the `=`. Fixed in `ytdl.bat` by using `%*` instead of `%~1`. **Not an issue in the Linux bash version** (bash doesn't split on `=`), so `ytdl` (Linux) just uses plain `"$1"`.
- **PowerShell 5.1 → pwsh 7 migration**: `pwsh` is genuinely cross-platform (this is *why* the Linux port was low-effort). Changes made: `$PSNativeCommandUseErrorActionPreference = $false` (quiets noisy `NativeCommandError` stderr wrapping — a no-op on 5.1, functional on 7), dropped `-UseBasicParsing` from `Invoke-WebRequest` (only ever needed to avoid 5.1's IE-engine dependency, which 7 never has), switched the original-thumbnail download to `-OutFile -PassThru` instead of reading `.Content` into memory (avoids relying on `.Content`'s not-fully-consistent binary-response typing). **Action item flagged to the user**: the old `download.log` was UTF-16 (5.1's default); appending pwsh's UTF-8 output onto it would corrupt the file, so it needs to be deleted/renamed before first use under pwsh — not something Claude can verify was actually done.
- **Windows `MAX_PATH` (260 chars)**: mitigated via the filename-shortening scheme above, `.40s`/`.60s` field truncation on folder names, and (offered but the user declined) `LongPathsEnabled`. Found and flagged an important caveat: Explorer itself never supports long paths even with that registry key set (per Microsoft's own docs) — so truncation, not registry changes, is the primary defense. **Not relevant on the Linux port** (ext4 allows ~4096-byte paths).
- **YouTube's newer "multiple credited channels/co-authors" feature is NOT supported by yt-dlp** — confirmed via an open, unresolved GitHub issue (yt-dlp/yt-dlp#14567). Only the primary uploader is ever captured; there is no current workaround.
- **Empty-folder sweep safety** (under `_incomplete`/temp): double-protected — an explicit "is this dir actually empty" check, AND `Remove-Item` without `-Recurse` independently refuses to delete non-empty directories regardless. Confirmed safe, not a blind wipe.
- **Dependency auto-update**: yt-dlp gets a real, safe, throttled (once/24h) self-update (`yt-dlp -U`). ffmpeg and pwsh deliberately do NOT auto-replace themselves mid-run (pwsh replacing its own running binary is genuinely risky; ffmpeg has no self-update mechanism) — instead there's a throttled check-and-warn (Windows: winget/gyan.dev version comparison; Linux: `apt list --upgradable`).
